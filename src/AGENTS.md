# 项目协作约束

## 必须保持

- 目标是拓扑正确的单层商超二维布局。JEPA 是预测和地点关联机制，BEV 是局部结构表征，全局图是可审计记忆。
- 推理保留小型 predictor；“JEPA 仅离线预训练，线上直接检索”不是最终实现。
- 不增加 VO、SLAM、SfM、GlueMap、VidMap、稠密重建或深度依赖来绕过研究难点。
- 不安排消融实验，不写未经验证的性能和论文首创结论。
- 文档和阶段报告使用中文；代码命名、类型注解、简短代码注释可用英文。

## 数据与证据

- 未观察 / 无标注 / 被遮挡必须显式表示，不能默认为可通行或无货架。
- 结构概率与证据状态分开。预测出口不是 verified 通行边。
- 地点关联、同一货架、实际走通是不同关系；错误合并必须可撤销。
- 训练教师额外帧只进入教师/监督；在线分支及历史缓存不能泄漏隐藏帧。
- 地图 snapshot 按时间和 evidence ID 冻结。GT 地图只生成标签，不作为在线输入。
- 同一物理门店的全部任务必须属于同一数据划分。
- RGB-only 不保证尺度/方向可辨识；对齐不可靠时输出 unknown / defer。

## 代码与交付

- 先运行现有测试；禁止用删除断言或扩大容差掩盖逻辑错误。
- 无外部下载的 CPU smoke 必须保留；研究模型可另配可选依赖与权重。
- 配置、schema、代码同步变更；未知配置项应显式报错。
- 禁止在测试中访问网络；无用户授权不下载大模型、不上传门店图片。
- 出错应包含样本/任务 ID；不捕获异常后静默生成一张完整地图。
- 不进行破坏性 git 操作；按最小模块修改，不重写已通过的无关代码。
- 每阶段更新 IMPLEMENTATION_STATUS.md，写明真实命令、环境、产物和未完成项。
- 不在仓库提交数据集、checkpoint、API 密钥、缓存、虚拟环境或伪造指标。

## 完成定义

实现 = 代码存在 + 可复现命令 + 针对测试通过 + 适用边界说明。真实能力验收需真实/合成结构数据；随机 smoke 只表示接口可运行。
