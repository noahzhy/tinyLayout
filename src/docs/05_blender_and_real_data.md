# 05 · 数据生产方案

## Blender 的交付目标

生成 RGB、二维局部结构标签、图、可见性和帧—区域对应；不是只渲染一排漂亮货架。现有 Blender 场景可复用，但本包没有假定其文件、单位或资产结构。

每个门店生成：通道/交叉通道、货架面、端架、冷柜、入口/墙、少量不规则区域。身份 ID 使用 store-scoped UUID；不同货架可共享完全相同材质，防纹理捷径。

## 可配置采集

模拟沿通道移动、侧拍、原地扫视、反向经过、路口转场、暂停与异地重启。按 0.5 秒间隔导出，但速度和动作随机，不能让时间成为米数。遮挡加入购物车/人员、模糊与曝光变化；相机姿态多样化，不只渲染完美朝前视图。

合成 pose/depth 仅用于离线标签/可见性生成，不导入线上模型。图像中不要打印真实地点 ID、坐标、彩色独有编码等泄漏线索。

## 标签产物

| 文件 | 内容 |
|---|---|
| `frames.jsonl` | store/task/segment/frame/time/path |
| `windows.jsonl` | context/hidden/teacher/anchor/snapshot |
| `charts/*.json` | 坐标规范与归一化跨度 |
| `labels/*.npz` | 语义、边界、开口、support、valid masks |
| `local_graphs/*.json` | node/port/edge/order/side |
| `global_graph.json` | 独立 GT，仅用于训练监督与质量审核 |
| `provenance.json` | 场景种子、资产版本、生成器 commit、许可证 |

可见性可由离线几何/实例 ID pass 和射线检查生成，但应验证透视遮挡、货架底部被挡等情况。未被实际观察支持的 GT 区域不进入 teacher_support。

## 成对拓扑场景

保留相同货架和纹理，改变支路顺序、端口排列或连接；保留同一拓扑，更换商品纹理和光照。反事实不能总是非法自交或超出图范围，否则网络只学到“这张图坏了”。

训练生成器与独立验收场景使用不同布局 seed 和资产组合；不能把同一家店的不同轨迹分到不同集合。

## 真实数据最小人工工作

以 task 为单位标连续片段、地点/路口身份、实际通行、主通道顺序和重复相似地点。只有局部二维标注对齐充分时才进入稠密 BEV 监督。未观察通道标 unknown。

先选一小组能覆盖“正常连续、重复通道、侧拍、断序列、遮挡”的任务完成协议闭环，数量由实际数据可得性决定，不把它写成论文统计结论。

## 数据阻塞处理

没有 Blender 文件或真实样本时，Codex 先实现独立导出协议、校验器、可见性字段和可配置场景构建入口。随机 tensor smoke 可继续，但不能替代真实 RGB/BEV 学习。

禁止为了展示闭环把俯视标签图直接当 RGB 输入；那会跳过本项目最核心的透视→BEV 难点。
