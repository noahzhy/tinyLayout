# 02 · BEV 坐标与可观测性契约

## 必须先解决的边界

仅 RGB 且没有尺度锚点时，真实绝对尺度不能凭表示形式获得；镜头侧拍、低头、反向经过也会改变可见内容。学习式 BEV 的对齐能力需要数据和监督，不因“没有显式位姿输入”而自动成立。

本版采用 **单片段局部 chart + 固定归一化跨度 + 全局拓扑拼接**。跨 chart 不直接逐像素融合；先做地点、端口和顺序关联。

## 局部 chart v1

- 选择 `anchor_frame_id`，必须存在于 online context，不能事后从隐藏 target 选一个最有利帧。
- 训练 chart 原点由数据生产侧定义为 anchor 相机对应的地面投影点；+y 为 anchor 光轴的水平投影，+x 为其右方。这里不把相机朝向当成行进方向。
- Blender 可使用真实相机姿态生成标签；这些姿态是 **训练侧特权信息**，不作为部署模型输入。
- 真实数据必须提供同义的局部结构对齐标注，或只使用 topology-only 标签；不能用未验证的相机高度/朝向假设生成伪精确 BEV。
- 固定共享的正方形 chart span。记录 `unit_mode=normalized` 与 `span_units`；度量跨度仅用于有尺度的合成标签。默认模型坐标 x,y∈[-1,1]。
- 一个样本的所有 context / teacher / observation / labels 使用同一个 chart；不允许每组独立 bbox 归一化。
- anchor 朝向退化（例如近乎垂直看地面）、结构无法确定或标注没有局部对齐时，显式标记 `chart_valid=false`，跳过逐格 BEV loss，不能让程序硬凑方向。

v1 使用 H_b=W_b=16 的方形网格。此前讨论的 16×32 可以作为未来配置；本包统一为 16×16，避免 90° 方向假设导致网格形状和空间跨度不一致。

## 张量到坐标

`B[:, row * W + col, :]` 对应 cell center：

```text
x = -1 + 2 * (col + 0.5) / W
 y =  1 - 2 * (row + 0.5) / H
```

row=0 是 chart 的前方（+y），col=0 为左方（-x）。连续坐标用于监督/图形输出时必须记录同一规范。示意图的 screen y 向下，只在 renderer 适配，不能反过来更改模型坐标。

## 三种 mask，不能互换

| mask | 说明 | 典型来源 |
|---|---|---|
| `context_valid_frames` | 哪些帧是真的，不是 padding | 数据加载 |
| `teacher_support` | 教师的额外观察支持哪些 BEV cell | 合成可见性 / 人工标注 |
| `target_region` | 本次要预测的结构区域 | 遮挡/查询采样 |

JEPA loss 使用 `teacher_support & target_region & chart_valid`，而不是自动把所有 cell 当真值。`label_valid` 另行控制真实结构监督；已知但当前不可见的监督可以显式添加，不能默认为观测证据。

未观察不是语义类别“空”。语义标签用 -1 表示 ignore；支持度由独立头预测，并保留标注来源。预测 support 只能影响排序/筛选，不能单独升级证据状态。

## 旋转和跨窗口关系

局部 BEV 可以使用四个轴向对齐假设，但必须保留任意角/未知分支。不同光轴角度通常不是精确 90°。旋转坐标系 ≠ 把 RGB 图片在平面中旋转；镜像也不是旋转，不允许左右分支偷换。

v1 在没有可靠方向/尺度对齐时 **仅更新图关系，不比较逐格 latent**。候选评分需要先对齐或使用经过训练的结构匹配模块；当前代码的 `candidate_energy` 要求输入已经位于相同 chart，未实现自动对齐。

## 不可辨识时的行为

全同外观、全同局部结构、没有额外观察时保留多个候选或 DEFER。没有真实转场证据的两个片段保持独立；拒绝用“商超一般很规整”补出通道。输出 JSON 中区分 `schematic_xy`、`normalized_chart_xy`、`metric_xy=null`。
